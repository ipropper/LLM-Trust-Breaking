# Monitor study: reading intent from the outside

Can a monitor that sees only an agent's public message and action tell whether the agent privately planned to deviate from its announcement? This folder holds the study built for the Apart Research AI Collusion Research Sprint (Oct 23–25, 2026).

## Pre-existing vs. new work

**Pre-existing (not ours):** the game harness and three-stage protocol in this repository (`src/`, `experiments/`) are from Shi et al. (2026), *When Agents Lie: Premeditation, Persistence, and Exploitation in Repeated Games* ([arXiv:2607.05132](https://arxiv.org/abs/2607.05132)), forked from the original repository.

**New during the sprint (Oct 23–25, 2026):**
- everything in `monitor_study/`: answer key and records (`records.py`), the monitor (`monitor.py`, `run_monitor.py`), the positive control (`positive_control.py`), the standard dataset export (`export_dataset.py`) and the analysis notebook (`analysis.ipynb`);
- small harness fixes: OpenRouter routing for OpenAI models, JSON-schema enforcement and retries (PRs #1 and #4), and in `src/endogenous/core/trial_runner.py` treating DeepSeek V4 as a reasoning model with an 8,000-token reply limit;
- all game runs, monitor runs and results in `results/`.

## Results

- `results/all_games.csv`: 670 agent-rounds × 3 monitors (2,010 rows), one standard format across six games. Column definitions: `results/COLUMN_KEY.md`.
- `results/figures/`: every figure in the report, regenerated by `analysis.ipynb`.

## Reproduce

```
cd monitor_study
../.venv/bin/python run_monitor.py --log <game log .json>        # one game log, three views, every model in monitor.MODELS
../.venv/bin/python positive_control.py <game logs .json ...>     # monitor also sees the private plan; should score near 100%
../.venv/bin/python export_dataset.py <game logs .json ...>       # standard per-game CSVs + all_games.csv
```

Game logs are generated with `experiments/run_endogenous.py` (DeepSeek V4 Pro in every seat, `REASONING_EFFORT=medium`, `--trials 5 --rounds 4 --round-robin --use-queue`).
